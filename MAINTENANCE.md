# Обслуживание сайта shelamov.ru — рецепты правок

Практические инструкции по типовым задачам. Общая архитектура — в `README.md`.

> **Главное правило.** Есть два уровня:
> - **Быстрая правка** — отредактировать готовый `.html` в корне и запушить.
>   Просто, но пропадёт при следующем запуске `tools/build.py`.
> - **Правильная правка** — изменить генератор/конфиг и пересобрать (`build.py`).
>   Переживает пересборку. Требует локального `tools/cache/` (см. README).
>
> Для разовых мелочей хватает быстрой правки. Для всего, что может повторяться, —
> правильной.

После любой правки:
```bash
python3 tools/build.py        # если меняли через генератор
python3 -m http.server 8765   # посмотреть локально на http://localhost:8765/
git add -A && git commit -m "…" && git push
```

## 1. Поправить текст / опечатку в стихотворении

**Быстро:** открыть `st/<сборник>/<стих>/index.html`, найти нужную строку
`<span class="l" …>…</span>` и исправить текст. Запушить.

Отступ «лесенки» задаётся атрибутами `style="--i:N" data-i="N"` (N — число
символов сдвига). Точное выравнивание потом наводит `assets/poem-align.js`.

> Один и тот же стих может быть в нескольких сборниках — поправьте во всех копиях
> (или правьте через исходник в `tools/cache/` и пересоберите).

**Правильнее — через исходник:** исправить текст в `tools/cache/st__<сборник>__<slug>.html`
и пересобрать (`python3 tools/build.py`). Тогда правка не потеряется при будущих
пересборках. Учтите: опечатка обычно повторяется в файле кэша 2–3 раза
(Google Sites дублирует текст в метаданных) — заменяйте все вхождения.

**Известный класс опечаток исходника — OCR:** цифра `6` вместо буквы «б»
(«не6ес», «се6е», «гри6ов»), слипшиеся/битые слова («вруг» → «вдруг»,
«наруку» → «на руку», «по воз» → «под воз»). Партия таких опечаток исправлена
04.07.2026 (7 слов с «6» + 3 слова). Проверить, не осталось ли новых:
```bash
grep -rhoE '[а-яА-ЯёЁ]6|6[а-яА-ЯёЁ]' st --include=index.html | sort -u
```

> **Побочный эффект:** если из-за опечатки два одинаковых стиха в разных
> сборниках считались «разными», после исправления они станут идентичными,
> и копия автоматически получит canonical и уйдёт из sitemap (см. раздел 10) —
> это нормально и правильно.

## 2. Добавить песню (mp3) к стихотворению

1. Положить файл в `music/` с простым именем латиницей, напр. `music/pesnya.mp3`.
2. В `tools/build.py` в словарь `AUDIO` добавить строку:
   ```python
   AUDIO = {
       "za-klukvoj": "vstali-do-rassveta.mp3",
       "o-materi":   "kvas-varganili.mp3",
       "<slug-стиха>": "pesnya.mp3",   # ← новая
   }
   ```
   `<slug-стиха>` — это часть URL: для `/st/samoe-dorogoe/za-klukvoj/` slug = `za-klukvoj`.
   Песня появится на всех копиях стиха во всех сборниках.
3. `python3 tools/build.py`, проверить, запушить.

## 3. Добавить / заменить электронную книгу (.ibooks)

1. Положить файл в `books/`, напр. `books/Novaya_kniga.ibooks`.
2. В `tools/build.py` в список `BOOKS` добавить кортеж `(файл, «Название»)`:
   ```python
   BOOKS = [
       ("Naotcheystorone.ibooks", "На отчей стороне"),
       ("Samoe_dorogoe.ibooks",   "Самое дорогое"),
       ("Strofarii.ibooks",       "Строфарии"),
       ("Novaya_kniga.ibooks",    "Новая книга"),   # ← новая
   ]
   ```
3. Пересобрать, запушить. Размер файла подставляется автоматически.

## 4. Поправить / добавить ссылку «полный текст» под цитатой (статьи об авторе)

Цитаты в статьях Сытина/Кузнецовой автоматически связываются с нашими стихами.
Если какая-то цитата не нашлась (искажение текста / OCR), добавьте её вручную в
`MANUAL_LINKS` в `tools/build.py`:

```python
MANUAL_LINKS = {
    "а походах щеки впалые": ("na-otchey-storone", "v-more"),
    "<первая строка цитаты в нижнем регистре, ё→е, только буквы и пробелы>":
        ("<сборник>", "<slug стиха>"),
}
```
Ключ — **нормализованная первая строка цитаты**: всё в нижний регистр, `ё`→`е`,
оставить только русские буквы и пробелы (знаки/кавычки убрать).

Пересобрать, запушить.

## 5. Посвящение / эпиграф (курсив справа)

Посвящения определяются автоматически — это строки, которые в исходнике
(`tools/cache/`) были **курсивом** (`<em>`). Короткие → курсив справа
(`.dedication`), длинные примечания → отдельный курсивный блок (`.epigraph`).

- Если посвящение **не распозналось** (его не было курсивом в оригинале) —
  проще всего в готовом `st/.../index.html` обернуть строку:
  замените `<div class="poem"><span class="l">Имя</span>…` — вынесите строку
  посвящения в `<div class="dedication"><span>Имя</span></div>` **перед**
  `<div class="poem">…`.
- Правка «на века» — пометить строку курсивом в исходнике в `tools/cache/<…>.html`
  (обернуть в `<em>…</em>`) и пересобрать.

## 6. Изменить дизайн (цвета, шрифты, отступы)

Всё оформление — в `assets/style.css`. Ключевые переменные в начале файла (`:root`):
```css
--paper   фон страницы (кремовый)
--ink     основной текст
--accent  акцент (кирпично-красный)
--maxw    ширина колонки чтения
--serif   основной шрифт
```
CSS правится напрямую (он не генерируется). Запушить — применится сразу.
Блоки помечены комментариями: «Шапка», «Стихотворение», «Поиск», «Песня» и т. д.

## 7. Добавить новое стихотворение

Сложнее всего, т. к. структура завязана на исходник. Варианты:

**А. Через готовый HTML (быстро).**
1. Скопировать папку существующего стиха, напр.
   `st/na-otchey-storone/abramcevo/` → `st/na-otchey-storone/<новый-slug>/`.
2. В `index.html` заменить заголовок (`<h1 class="page-title">`, `<title>`,
   canonical, breadcrumbs) и строки стиха (`<span class="l">…`).
3. Поправить prev/next у соседних стихов вручную (ссылки `.prev`/`.next`).
4. Добавить стих в `tools/struct.json` (в нужный сборник, в нужное место порядка) —
   чтобы он попал в оглавление и в поиск при следующей пересборке.

**Б. Через исходник (правильно).**
1. Создать страницу-снапшот в `tools/cache/st__<сборник>__<slug>.html` по образцу
   существующей (заголовок в `<h1>`, строки в `<p class="CDt4Ke zfr3Q">`,
   отступы — ведущими пробелами, посвящение — `<em>`).
2. Добавить slug в `tools/struct.json`.
3. `python3 tools/build.py` — страница, prev/next, оглавление, поиск обновятся сами.

## 8. Поиск

Поиск работает на `search-index.json`, который **генерируется** `build.py` из всех
стихов и статей. Отдельно править индекс не нужно — он пересобирается. Логика
поиска — в `assets/search.js` (подсветка, сниппет, сортировка: совпадения в
заголовке выше).

## 9. SEO-панели (сделано, текущее состояние)

Обе панели подключены; права подтверждены HTML-файлами в корне
(`googlee4a795479a3aa0fa.html`, `yandex_d44ae023481ae969.html` — **не удалять**),
sitemap отправлен в обе.

**Google Search Console** (ресурс-префикс `https://shelamov.ru/`).
Отчёт «Индексирование → Страницы» показывает две «причины неиндексации» —
обе штатные, паниковать не надо:

- **«Страница с переадресацией»** — это URL без завершающего слэша
  (`…/st/x/y` → 301 → `…/st/x/y/`). Так работает GitHub Pages; Google просто
  сообщает, что сами редиректы не индексирует. Ничего делать не нужно.
- **«Страница является копией. Канонические версии… не совпадают»** — стих-дубль
  из нескольких сборников. С 04.07.2026 решается автоматически тегами canonical
  (раздел 10). По обеим причинам 03.07.2026 запущены «Проверить исправление»
  (результат приходит на почту через 1–2 недели).
  Проверка 25.07.2026 завершилась «ошибкой»: для ~6 стихов Google продолжает
  держать каноничными адреса старого сайта (другие сборники, `www.`, без
  слэша), хотя наша разметка верна. Это решает только сам Google по мере
  переобхода; чтобы он быстрее увидел актуальную карту, в sitemap с 09.10.2026
  проставляется `<lastmod>` (см. ниже) и sitemap переотправлен вручную.

**`<lastmod>` в sitemap** проставляет `build.py` (`lastmod()`): дата последнего
коммита, менявшего `index.html` страницы; если пересборка только что изменила
файл — сегодняшняя дата. Поэтому `build.py` нужно запускать внутри git-репо;
незначимые пересборки (файл не изменился) дату не сдвигают.

**Яндекс.Вебмастер:** sitemap подан, переобход — «Индексирование → Переобход
страниц», лимит 150 URL/сутки. Региональность намеренно не задана.

## 10. Дубли стихов между сборниками и canonical

Один стих может входить в несколько сборников — это соответствует бумажным
изданиям и сохранено с оригинального сайта. Чтобы поисковики не считали копии
конкурирующими страницами, `build.py` расставляет canonical автоматически:

- **Дубль** = совпадают заголовок **и** полный текст (после нормализации;
  пунктуация/регистр не в счёт). Логика — словарь `CANONICAL_OF` в `build()`.
- **Канонической** считается копия в самом раннем по публикации сборнике —
  порядок задаёт список `COLLECTIONS`: На отчей стороне → Самое дорогое →
  Строфарии → Вне сборников.
- У копий `rel=canonical`, `og:url` и `url` в JSON-LD указывают на каноническую
  версию; из `sitemap.xml` копии исключены (129 URL вместо 181; копий — 52).
- Сами страницы-копии живут как раньше: открываются, листаются prev/next,
  участвуют в поиске по сайту. Canonical — только подсказка поисковикам.

**Осознанные исключения** (одинаковое название, но разные редакции — canonical
не ставится, обе версии самостоятельные):
- «Заяц» — в «Строфариях» добавлено посвящение В. П. Солдатову;
- «Учитель» — в «Самом дорогом» посвящение И. М. Селезнёву;
- «Памяти павших» — в «Самом дорогом» предисловие о братской могиле в Протасове.

Ничего настраивать вручную не нужно: при добавлении/правке стихов пересборка
сама пересчитает дубли. Если правите опечатку в одной из копий — правьте в
кэше обеих (раздел 1), иначе стихи «разойдутся» и copy перестанет
канонизироваться.

## Шпаргалка по командам

```bash
# Пересобрать сайт
python3 tools/build.py

# Локальный просмотр
python3 -m http.server 8765

# Опубликовать
git add -A && git commit -m "описание" && git push

# Статус сборки Pages
gh api repos/5r4rw6n9n2-svg/5r4rw6n9n2-svg.github.io/pages/builds/latest

# Деплой упал («Deployment failed, try again later») — запросить пересборку заново
gh api -X POST repos/5r4rw6n9n2-svg/5r4rw6n9n2-svg.github.io/pages/builds

# Проверить страницу вживую (в обход локального DNS)
curl -sI --resolve shelamov.ru:443:185.199.108.153 https://shelamov.ru/
```

**Нюансы публикации** (случай 03–04.07.2026):
- Деплой Pages может упасть с ошибкой GitHub «Deployment failed, try again
  later» (письмо от Actions, run красный) — это сбой на их стороне, коммит
  ни при чём. Перезапуск воркфлоу (`gh run rerun <id> --failed`) может надолго
  зависнуть в очереди; надёжнее сразу `gh api -X POST …/pages/builds` (команда
  выше) — пересобирает сайт из текущего `main` мимо зависшего рана.
- После успешного деплоя CDN отдаёт старую версию ещё до ~10 минут
  (`cache-control: max-age=600`). Свежесть видно по заголовку `last-modified`
  (`curl -sI <url>`), а не по содержимому первой попавшейся выдачи.
